# Splunk Practice Lab – Log Analysis & Investigation

## Overview

In this project, I am practicing working with Splunk as a basic SIEM tool. I use it to search, analyze, and investigate log data in order to better understand how security monitoring works in real environments.

I focus on learning how to navigate large amounts of log data and how to identify important events that could indicate suspicious activity or incidents.

---

## What I am doing in Splunk

In Splunk, I mainly work with **New Search** functionality, where I write queries to explore different datasets.

I am learning how to:
- Search through logs using SPL (Search Processing Language)
- Filter and narrow down results based on time range and fields
- Work with different visualization options
- Understand patterns in log data

---

## Search and Visualization Options

When I run searches, I explore different ways of analyzing results:

- I use **timeline view** to understand when events happened
- I switch between **linear and logarithmic scaling** to better visualize data with large differences in volume
- I focus on identifying peaks, anomalies, and unusual patterns in logs
- I often adjust time ranges to compare activity in different periods

These features help me understand how security analysts detect abnormal behavior in real systems.

---

## Understanding Log Areas

In my current practice datasets, I usually work with logs that can be divided into two main areas where activity occurs.

I analyze both sections to understand:
- what kind of events are happening
- when unusual activity appears
- how different systems behave over time

This helps me build a basic understanding of how incidents can be detected across multiple sources.

---

## Security Thinking

I am learning that companies heavily rely on log data to detect security issues early. Because of that, it is important to be able to navigate logs efficiently and understand what is normal and what is not.

When I approach a problem, I try to think like this:
- What is normal behavior in the system?
- What looks unusual or unexpected?
- What data can confirm or deny a suspicion?

This mindset is important for SOC and incident response roles.

---

## My Learning Approach

I actively try to simulate real-world scenarios and treat Splunk as if I was working in a security operations center.

When I learn something new, I:
- test it in searches
- observe results
- try to break down what the logs are showing me
- document my findings

I also try to improve my understanding by asking for structured learning materials, examples, and real-world use cases from employers or training environments.
